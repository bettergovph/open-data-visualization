# Integrated 2026 Implementation Plan

> [!NOTE]
> This document outlines the roadmap for the **Integrated 2026** initiative. The core objective is to cross-reference **"Resurrected Projects"** with **"Flagged Amount Projects"** (projects linked to flagged contractors or dynasties via the CAT tool) to identify high-risk budget items. It relies on a new unified location database keying into 2025 election districts.

## 1. Unified Location Database (The Foundation)
**Goal:** Create a single, precise source of truth for location data that maps every Barangay to its 2025 Legislative District and assigning Congressman.

- **Inputs:**
    - **Administrative Boundaries:** `philippine_provinces_cities_municipalities_and_barangays_2019v2.json` (Hierarchy)
    - **DILG 2025 Data:** `data/dilg/*.json` (Official Barangay list)
    - **Comelec 2025 Data:** `ph-elections2025/data/` (Precinct-level district mapping)
- **Output:** `static/data/unified_locations.duckdb` (and JSON) containing:
    - `region`, `province`, `municipality`, `barangay`
    - `district` (e.g., "1st District", "Lone District")
    - `congressman` (Mapped from `congressman-ranking.json` using the district)

### Action Items:
1.  **Create `scripts/build_unified_location_db.py`:**
    - Load DILG data as the master list of barangays.
    - Crawl Comelec CSVs to map each Municipality/City to its Legislative District.
    - Resolve "Lone Districts" and complex split districts (if any).
    - Save to DuckDB/Parquet for fast querying.

## 2. Enrichment & Cross-Referencing
**Goal:** Use the unified location data to "tag" projects in our existing datasets and find the intersection of risks.

### A. Enrich Resurrected Projects (`#resu`, `#resu2`)
- **Script:** Update `scripts/find_resurrected_projects_duckdb.py`.
- **Logic:**
    - For each resurrected project match, attempt to extract strict location info (Barangay/Municipality).
    - Query `unified_locations.duckdb` to assign a **Legislative District**.
    - Tag the project with the **Incumbent Congressman** for that district.

### B. Enrich Flagged Amount Projects (`#cat`)
- **Script:** Update `scripts/generate_dynasty_projects_cache_duckdb.py`.
- **Logic:**
    - Currently, it uses loose matching. Update it to use the strict `unified_locations.duckdb` for better district assignment.
    - Ensure every Flagged/Dynasty-linked project has a high-confidence district assignment.

### C. Prioritization Logic & Ranking
- **Concept:** A project is **High Priority** if it appears in **BOTH**:
    1.  **Resurrected List** (Revised Name match).
    2.  **Flagged Amount List** (Linked to flagged contractors/dynasties via CAT tool).

- **Aggregation & Ranking:**
    - The goal is to aggregate these high-risk projects by **Legislative District**.
    - **Rank Districts/Congressmen** by:
        1.  **Total Count** of overlapping projects.
        2.  **Total Amount** of overlapping projects.
    - This identifies which Congressmen have the highest concentration of "Resurrected & Flagged" projects.

## 3. The Secret Dashboard (`/integ2026`)
**Goal:** A simplified, high-density view for internal analysis of these prioritized projects.

### Frontend (`templates/budget.html` or new template)
- **Route:** `/integ2026` (Hidden from main nav).
- **Layout:**
    - **Summary Scorecard:** Total High-Risk Amount, Top Congressmen involved.
    - **The "Integrity Table":**
        - Columns:
            - **Rank**
            - **Project Name** (2026)
            - **Amount**
            - **Risk Factors** (Tags: 🔄 Resurrected 3y, 🚩 Flagged: Zaldy Co)
            - **Location** (District + Congressman)
            - **Historical Match** (Year + Amount)
- **Data Source:** A new pre-calculated JSON `static/data/integrated_matrix_2026.json` generated by a new script `scripts/generate_integrated_matrix.py`.

## 4. Implementation Steps (Agent Handoff)

1.  **Build Location DB:** Run `scripts/build_unified_location_db.py`. Verify typical ambiguous municipalities.
2.  **Update Resurrected Script:** Modify `find_resurrected_projects_duckdb.py` to load the new Location DB and add a `legislative_district` + `congressman` column to the output JSON.
3.  **Update Dynasty/Flagged Script:** Ensure `generate_dynasty_projects_cache_duckdb.py` aligns with the new location logic.
4.  **Generate Matrix:** Create `scripts/generate_integrated_matrix.py` that loads:
    - `resurrected_projects_dpwh.json`
    - `resurrected_projects_dpwh_revised.json`
    - `dynasty-projects-cache.json`
    - Performs the intersection and sorting.
    - Outputs `integrated_matrix_2026.json`.
5.  **Build UI:** Add the `/integ2026` view to the frontend to render this matrix.
